CacheLite / Architecture

一个带 MySQL 回源的
高并发内存 KV 服务器

整体架构

网络线程负责事件分发和响应顺序；后台线程负责可能阻塞的数据库查询。

模块职责

每层只处理自己的问题，通过接口连接，避免网络、协议、存储和数据库逻辑互相耦合。

NETWORK

网络层

Socket、InetAddress、Buffer、EpollPoller 封装 TCP、地址、缓冲区和 epoll。

PROTOCOL

RESP 协议层

RespParser 处理半包和粘包，RespEncoder 将结果编码为 RESP2 响应。

COMMAND

命令层

CommandExecutor 负责 SET、GET、DEL、EXPIRE、TTL 等命令语义，并生成 AOF 命令。

CACHE

缓存服务层

CacheService 统一封装内存读写、后台 worker 和异步回源任务队列。

STORAGE

内存存储层

MemoryStore 保存 String KV，维护 TTL、内存占用、精确 LRU 链表和超限淘汰。

DATABASE

数据库层

KeyValueRepository 定义抽象；MySQLRepository 查询；MySQLConnectionPool 复用连接。

PERSISTENCE

AOF 持久化

AofLog 追加记录修改命令，启动时重放 AOF；GET 等只读命令不会写入 AOF。

BUILD

构建与配置

CMake 通过 CACHELITE_ENABLE_MYSQL 控制 MySQL 功能，运行时从环境变量读取连接配置。

SCOPE

当前边界

当前聚焦单机 String KV；暂不包含集群、主从复制、事务、Lua、Pub/Sub 和 AOF 重写。

GET 未命中：异步 MySQL 回源

这是当前版本最有区别于普通 MiniRedis 的业务链路：数据库查询不会阻塞 epoll 主线程。

1 · 收包epoll_wait → Socket::read
→
2 · 解析Buffer → RespParser
→
3 · 查内存CacheService → MemoryStore
4 · 入队lookupAsync → condition_variable
→
5 · 查 MySQLworker → Repository → Pool
→
6 · 回通知callback → CompletionQueue → eventfd
7 · 回填processCompletions → MemoryStore::set
→
8 · 编码RespEncoder → output buffer
→
9 · 发送EPOLLOUT → Socket::send
同一客户端回源期间由 pendingRequestId 保护响应顺序；查询完成后才继续处理该客户端后续请求。

线程与事件模型

主线程和 worker 线程各自负责不同类型的工作，通过线程安全队列与 eventfd 交接。

EPOLL THREAD

主事件线程

  • 等待客户端 socket 和 eventfd
  • 读取数据、解析 RESP
  • 处理内存命中请求
  • 组织响应并发送数据
WORKER THREADS

缓存回源线程

  • 等待 condition_variable
  • 消费 CacheService::tasks_
  • 借用 MySQL 连接执行查询
  • 通过 callback 投递结果
HANDOFF

线程安全交接

  • 任务队列由 mutex 保护
  • 完成队列由 mutex 保护
  • eventfd 唤醒 epoll 主线程
  • 主线程独占客户端状态
客户端 socket --(epoll)--> 主线程 --(lookupAsync)--> tasks_ --(worker)--> MySQL
      ^                 |                                      |
      +--(EPOLLOUT)-----+ <-- eventfd <-- CompletionQueue <-----+

数据与持久化

MEMORY

MemoryStore

数据首先存在内存中。每个 key 关联 value、过期时间和 LRU 位置；超限后按 LRU 淘汰。

AOF

appendonly.aof

修改命令追加到 AOF。启动时由 AofLog::replay() 交给命令执行器重放。

MYSQL

cache_entries

MySQL 是缓存未命中的回源数据源。查询成功后只回填内存，不通过普通 SET 修改数据库。

当前的 MySQL 回源是 read-through：GET 未命中才查数据库，查到后回填内存；不是启动时全量加载，也不是每次 GET 都查 MySQL。
